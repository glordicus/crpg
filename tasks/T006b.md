## Task
Add the `Fx16_16` fixed-point type to `crpg-core`.

## Crate(s)
`crpg-core` (only).

## Purpose
The numeric type every rules value that is not a plain integer is expressed
in. `crpg-rules` may not use `f32`/`f64` at all (root AGENTS.md, and
`tools/lint/determinism.py` enforces it), so multipliers, rates and fractional
modifiers need an exact, deterministic alternative. ADR-0006 Decision 2 fixes
the semantics; this task implements them.

## Interface

```rust
// crates/crpg-core/src/fixed.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default,
         serde::Serialize, serde::Deserialize)]
#[serde(transparent)]
pub struct Fx16_16(i32);   // 16 fractional bits

impl Fx16_16 {
    pub const FRAC_BITS: u32 = 16;
    pub const ONE: Self;
    pub const ZERO: Self;
    pub const MIN: Self;          // from i32::MIN
    pub const MAX: Self;          // from i32::MAX
    pub const EPSILON: Self;      // one raw unit, 1/65536

    pub const fn from_raw(raw: i32) -> Self;
    pub const fn to_raw(self) -> i32;
    pub const fn from_int(v: i32) -> Self;          // saturating
    pub const fn to_int_floor(self) -> i32;
    pub fn from_ratio(num: i32, den: i32) -> Self;  // floors; den == 0 saturates by sign, as Div

    pub fn floor(self) -> Self;
    pub fn ceil(self) -> Self;
    pub fn round(self) -> Self;     // half away from zero; document it
    pub fn abs(self) -> Self;       // saturating: MIN.abs() == MAX
    pub fn signum(self) -> i32;
    pub fn is_negative(self) -> bool;
    pub fn is_positive(self) -> bool;

    pub fn checked_add(self, rhs: Self) -> Option<Self>;
    pub fn checked_sub(self, rhs: Self) -> Option<Self>;
    pub fn checked_mul(self, rhs: Self) -> Option<Self>;
    pub fn checked_div(self, rhs: Self) -> Option<Self>;   // None on rhs == 0
    pub fn saturating_add(self, rhs: Self) -> Self;
    pub fn saturating_sub(self, rhs: Self) -> Self;
    pub fn saturating_mul(self, rhs: Self) -> Self;
    pub fn saturating_div(self, rhs: Self) -> Self;
}

// Operators delegate to the saturating_* forms.
impl core::ops::Add for Fx16_16 { /* = saturating_add */ }
impl core::ops::Sub for Fx16_16 { /* = saturating_sub */ }
impl core::ops::Mul for Fx16_16 { /* = saturating_mul */ }
impl core::ops::Div for Fx16_16 { /* = saturating_div */ }
impl core::ops::Neg for Fx16_16 { /* saturating: -MIN == MAX */ }
impl core::ops::AddAssign / SubAssign / MulAssign / DivAssign
impl core::iter::Sum for Fx16_16          // saturating

impl core::fmt::Display for Fx16_16 { /* exact decimal */ }
impl core::str::FromStr for Fx16_16 { type Err = CoreError; }
```

## Behaviour
Three rules, and they are the whole design:

1. **Everything saturates. Nothing panics, nothing wraps.** The operator impls
   clamp at `MIN`/`MAX`. `Div` by zero saturates by the numerator's sign
   (positive → `MAX`, negative → `MIN`, zero → `ZERO`); `checked_div` returns
   `None`. Rationale is in ADR-0006 and worth restating in the module doc:
   Rust's default `i32` arithmetic panics in debug and wraps in release, and a
   simulation that behaves differently under two build profiles cannot be
   replayed.

2. **Every lossy operation rounds toward negative infinity.** `Mul` is
   `((a as i64) * (b as i64)) >> 16` — an arithmetic shift, so it floors for
   free. `Div` does not: Rust's `/` truncates toward zero, so subtract one when
   the division is inexact **and** the operands have opposite signs.
   `to_int_floor` floors. `round` is the one deliberate exception and is named
   for it.

   **Do not use `i64::div_euclid` for this.** It rounds toward −∞ only for a
   positive divisor; with a negative divisor it rounds toward +∞
   (`7i64.div_euclid(-2) == -3`, but the floor is `-4`). It is the obvious
   wrong reach here. Write the adjustment explicitly and put the counterexample
   in a test.

3. **`Display` is exact and round-trips.** Every `Fx16_16` is exactly
   representable as a decimal with at most 16 fractional digits. Print the
   shortest exact decimal (no trailing zeros, `"0"` for zero, `"-0.5"` with the
   sign on the integer part). `FromStr` accepts what `Display` emits, plus
   plain integers; it rejects anything else with a `CoreError` variant added by
   this task. Values with more precision than 1/65536 are **rejected**, not
   silently rounded — silent precision loss on authored data is worse than an
   error message.

## Constraints
- No new dependency. `serde` only, plus `proptest` and `serde_json` in dev
  (both added by T006a).
- No `f32`/`f64` anywhere, including in tests. If a test needs a reference
  value, compute it in `i64` — a float oracle would reintroduce exactly the
  imprecision this type exists to avoid.
- `#[serde(transparent)]` over the raw `i32`. Do not serialize as a decimal
  string; ADR-0006 defers the authoring-friendly representation to `crpg-data`.
- All arithmetic goes through `i64` intermediates before clamping back to
  `i32`. No `as i32` cast that can truncate silently.

## Test
Add `crates/crpg-core/tests/fixed.rs`.

Property tests over arbitrary `i32` raw values:
1. **Total, never panicking.** For every pair `(a, b)` proptest generates,
   `a + b`, `a - b`, `a * b`, `a / b`, `-a` and `a.abs()` all complete. No
   input panics or overflows, including `MIN`, `MAX` and zero divisors.
2. **Commutativity.** `a + b == b + a` and `a * b == b * a`.
3. **Identities.** `a + ZERO == a`; `a * ONE == a`; `a / ONE == a`;
   `a - a == ZERO`.
4. **Multiplication matches the exact i64 definition.** `(a * b).to_raw()`
   equals `(((a.to_raw() as i64) * (b.to_raw() as i64)) >> 16)` clamped to
   `i32`. This pins the rounding rule so a later "optimisation" cannot quietly
   change it.
5. **Division floors, including for negative divisors.** For `b != 0`,
   `(a / b).to_raw()` equals `q` computed in `i64` as: `n = (a.to_raw() as i64)
   << 16`, `d = b.to_raw() as i64`, `q = n / d`, then `q - 1` if `n % d != 0`
   and `(n < 0) != (d < 0)`; clamped to `i32`. Plus two explicit unit cases
   with a negative divisor:
   - `Fx16_16::from_int(7) / Fx16_16::from_int(-2)` is exactly `-3.5`
     (raw `-229376`). A sanity case; it is exact, so it does not discriminate.
   - `Fx16_16::EPSILON / Fx16_16::from_int(-3)` is `-EPSILON` (raw `-1`).
     **This is the case that matters.** Truncation gives `0` and `div_euclid`
     also gives `0`; only floor gives `-1`. Verified against the arithmetic
     before this task file was written.
6. **`from_int`/`to_int_floor` round-trip** for every `i32` in the
   representable integer range.
7. **`Display`/`FromStr` round-trip.** `parse(display(x)) == x` for arbitrary
   `x`. Plus unit tests for the shapes: `"1"`, `"-1"`, `"0"`, `"0.5"`,
   `"-0.5"`, `"1.0000152587890625"` (one epsilon above one), and rejection of
   `"0.1x"`, `""`, `"1.00000000000000001"` (too precise), and a value outside
   the representable range.
8. **Ordering agrees with the raw ordering** — `Ord` on `Fx16_16` matches `Ord`
   on `to_raw()`.
9. **Serde round-trip** `deserialize(serialize(x)) == x`, and a unit test
   asserting the JSON form of `ONE` is the bare integer `65536`.

Unit tests for the saturation boundaries specifically: `MAX + ONE == MAX`,
`MIN - ONE == MIN`, `MIN.abs() == MAX`, `-MIN == MAX`, `MAX * MAX == MAX`,
`ONE / ZERO == MAX`, `(-ONE) / ZERO == MIN`, `ZERO / ZERO == ZERO`,
`MAX.checked_add(ONE).is_none()`.

Command that must pass: `cargo test -p crpg-core`

## Out of scope
- Trigonometry, `sqrt`, `pow`, `exp`, interpolation helpers. None has a caller.
  Add them in the task that needs them.
- A second fixed-point width (`Fx8_8`, `Fx32_32`). Positions use `f32` outside
  the rules path per spec §2.4; nothing needs another width.
- Conversions to or from `f32`/`f64`. Deliberately absent — the type exists to
  make float contamination impossible, and a `From<f32>` is the hole through
  which it would arrive.
- A human-readable serde representation. ADR-0006 gives that to `crpg-data`.
- Any other module in `crpg-core`, any other crate.
