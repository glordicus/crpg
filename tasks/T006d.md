## Task
Add `Tick`, `RoundCount` and `Ulid` to `crpg-core`.

## Crate(s)
`crpg-core` (only).

## Purpose
`Tick` and `RoundCount` are the simulation's two units of time. Spec §2.5 is
firm that rules durations are expressed in rounds, turns or ticks and never in
seconds — a "6-second round" is ruleset data, not an engine constant — so these
types exist to make seconds unrepresentable. `Ulid` is the identity of every
authored campaign object (spec §4.3): generated once, never reused, never
changed, and the only thing cross-references are allowed to use.

## Interface

```rust
// crates/crpg-core/src/time.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default,
         serde::Serialize, serde::Deserialize)]
#[serde(transparent)]
pub struct Tick(u64);

impl Tick {
    pub const ZERO: Self;
    pub const fn new(v: u64) -> Self;
    pub const fn get(self) -> u64;
    pub fn next(self) -> Self;                       // saturating
    pub fn saturating_add(self, n: u64) -> Self;
    pub fn saturating_sub(self, n: u64) -> Self;
    pub fn checked_add(self, n: u64) -> Option<Self>;
    /// Ticks elapsed from `earlier` to `self`; 0 if `self` is earlier.
    pub fn since(self, earlier: Self) -> u64;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default,
         serde::Serialize, serde::Deserialize)]
#[serde(transparent)]
pub struct RoundCount(u32);
// same shape: ZERO, new, get, next, saturating_add/sub, checked_add, since

// crates/crpg-core/src/ulid.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Ulid(u128);

impl Ulid {
    pub const NIL: Self;
    /// 48-bit millisecond timestamp, 80-bit randomness. Both supplied by the
    /// caller — this crate has no clock and no entropy source.
    pub fn from_parts(timestamp_ms: u64, randomness: u128) -> Self;
    pub const fn from_u128(v: u128) -> Self;
    pub const fn to_u128(self) -> u128;
    pub fn timestamp_ms(self) -> u64;   // low 48 bits of the timestamp field
    pub fn randomness(self) -> u128;    // low 80 bits
}

impl core::fmt::Display for Ulid { /* 26-char uppercase Crockford base32 */ }
impl core::str::FromStr for Ulid { type Err = CoreError; }
// Serialize/Deserialize go through the string form, not the u128.
```

## Behaviour
**`Tick` / `RoundCount`**
- Newtypes with no arithmetic operators. `Add`/`Sub` impls are deliberately
  absent: `tick + 1` reads as if 1 were a tick, and every real call site should
  say `saturating_add(n)` or `next()` and mean it.
- All arithmetic saturates, consistent with `Fx16_16` (ADR-0006 Decision 2). No
  panics, no wrapping, no debug/release divergence.
- **No tick rate lives here.** Spec §2.5 says 20 Hz is "configurable, but
  tested at 20", which makes it server configuration, not a core constant. Do
  not add `TICKS_PER_SECOND`, `to_millis`, `from_seconds`, or a `Duration`
  conversion — the whole point of the type is that seconds are not
  representable at this layer.

**`Ulid`**
- 128 bits: timestamp in the high 48, randomness in the low 80.
- `from_parts` masks both arguments to their field widths rather than
  panicking on an over-wide input; document that it does.
- `Display` emits 26 uppercase Crockford base32 characters
  (`0123456789ABCDEFGHJKMNPQRSTVWXYZ` — no I, L, O or U).
- `FromStr` is case-insensitive, and maps the Crockford aliases on input:
  `I`/`L` → `1`, `O` → `0`. It rejects: any length other than 26, any
  character outside the alphabet after aliasing, and a first character above
  `'7'` (26 × 5 = 130 bits, so the leading character carries only 2 usable
  bits and anything larger overflows 128 bits).
- `Ord` on `Ulid` must agree with `Ord` on its `Display` string, which is what
  makes ULIDs lexicographically sortable by time. Test it.
- Serde uses the string form — spec §4.3 shows ULIDs as JSON strings
  (`"id": "01J8QK4W9YB6ZC3M0N7XKQ2R4A"`) and campaign data is human-authored
  and human-reviewed.

## Constraints
- No new dependency. No clock, no entropy, no `SystemTime`, no `rand`.
  Generation is the caller's job: `crpg-cli` and `crpg-edit` supply the
  timestamp and randomness when they author a new object. This keeps
  `crpg-core` usable from `crpg-rules` and `crpg-sim`, where the determinism
  lint bans both.
- Extend `CoreError` with the parse-failure variants this task needs. Messages
  name what was wrong (length, character, overflow), not just "invalid".
- No floats. No `HashMap`/`HashSet`.

## Test
Add `crates/crpg-core/tests/time.rs` and `crates/crpg-core/tests/ulid.rs`.

**Time**
1. Saturation: `Tick::new(u64::MAX).next() == Tick::new(u64::MAX)`;
   `Tick::ZERO.saturating_sub(5) == Tick::ZERO`; the same for `RoundCount` at
   `u32::MAX`.
2. `since` is 0 when the receiver is earlier, and exact otherwise. Property
   test over arbitrary pairs.
3. Serde round-trip, plus a unit test asserting `Tick::new(7)` serializes to
   the bare JSON number `7`.

**Ulid**
4. **String round-trip.** `parse(display(x)) == x` for an arbitrary `u128`.
   Property test.
5. **Field round-trip.** `from_parts(ts, rand)` has `timestamp_ms() == ts` and
   `randomness() == rand` for arbitrary inputs within the field widths, and
   masks correctly for inputs beyond them.
6. **Ordering.** For arbitrary pairs, `a.cmp(&b)` equals
   `a.to_string().cmp(&b.to_string())`. And for arbitrary timestamps
   `t1 < t2`, `from_parts(t1, r1) < from_parts(t2, r2)` regardless of the
   randomness.
7. **Case and alias handling.** `"01j8qk4w9yb6zc3m0n7xkq2r4a"` parses equal to
   its uppercase form; a string using `I`, `L` and `O` parses as if they were
   `1`, `1` and `0`.
8. **Rejection.** 25 characters, 27 characters, empty, a `U` in the body, a
   non-alphanumeric character, and `"80000000000000000000000000"` (first
   character `8`, which overflows 128 bits) each return an error — and the
   error names which of the three problems it was.
9. **Known vector.** The literal `"01J8QK4W9YB6ZC3M0N7XKQ2R4A"` from spec §4.3
   parses, and re-displays byte-identically.
10. Serde round-trip, plus a unit test asserting a `Ulid` serializes to a JSON
    *string*, not a number.

Command that must pass: `cargo test -p crpg-core`

## Out of scope
- ULID *generation*. No `Ulid::new()`, no `Ulid::now()`. The caller supplies
  the timestamp and the randomness; adding a clock or an entropy source here
  would make `crpg-core` unusable from the deterministic crates.
- `Turn`, `Initiative`, `Timeline`, turn order. The timeline is `crpg-sim`
  (T16). This task is two counters and an id.
- Any tick-rate constant, seconds/milliseconds conversion, or `Duration` type.
- The fixed-step accumulator loop (§19.1 item 9) — that is T008, and it lives
  in `crpg-server`/`crpg-testkit`, not here.
- Any other module in `crpg-core`, any other crate.
