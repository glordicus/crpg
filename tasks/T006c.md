## Task
Add `DeterministicRng` with named sub-streams to `crpg-core`.

## Crate(s)
`crpg-core` (only).

## Purpose
Every random decision in the simulation goes through this and nothing else —
`tools/lint/determinism.py` bans `rand::` and `thread_rng` in `crpg-rules` and
`crpg-sim` precisely so that there is one seeded source. Named sub-streams let
combat, loot and AI draw independently, so that adding an AI query does not
shift the combat dice and invalidate every golden replay. ADR-0006 Decision 3
fixes the algorithm and the ownership model.

## Interface

```rust
// crates/crpg-core/src/rng.rs

/// One PCG32 stream. 16 bytes of state.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct Pcg32 { /* private: state: u64, inc: u64 */ }

impl Pcg32 {
    pub fn next_u32(&mut self) -> u32;
    pub fn next_u64(&mut self) -> u64;
    /// Uniform over `[0, bound)`. Rejection sampling — no modulo bias.
    pub fn gen_range_u32(&mut self, bound: core::num::NonZeroU32) -> u32;
    /// Uniform over `[lo, hi]`, inclusive. Panic-free for any lo <= hi;
    /// returns `lo` if `lo == hi`. Document the behaviour when `lo > hi`.
    pub fn gen_range_i32(&mut self, lo: i32, hi: i32) -> i32;
    pub fn gen_bool(&mut self) -> bool;
}

/// The simulation's single source of randomness. Owns all its sub-streams,
/// so serializing this serializes every stream.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct DeterministicRng { /* private: seed: u64, streams: BTreeMap<String, Pcg32> */ }

impl DeterministicRng {
    pub fn from_seed(seed: u64) -> Self;
    pub fn seed(&self) -> u64;
    /// Borrow a named sub-stream, creating it on first use. Its parameters
    /// derive from `(seed, name)`, so first-use order does not affect output.
    pub fn stream(&mut self, name: &str) -> &mut Pcg32;
    /// Whether a stream has been touched. For diagnostics and tests only.
    pub fn has_stream(&self, name: &str) -> bool;
    pub fn stream_names(&self) -> impl Iterator<Item = &str>;
}
```

## Behaviour
- **PCG32-XSH-RR.** `state = state * 6364136223846793005 + inc`, output is the
  xorshift-high / random-rotate of the old state. `inc` is always odd.
- **Stream derivation.** `stream(name)` derives `(state, inc)` from `seed` and
  `name` via splitmix64 over the name's bytes mixed with the seed, forcing
  `inc` odd. It must be a pure function of `(seed, name)`: two
  `DeterministicRng`s built from the same seed that touch streams in different
  orders must produce identical output per stream.
- **Lazy creation is not observable.** Creating a stream must not advance any
  other stream, and must not depend on how many streams already exist.
- **`BTreeMap`, not `IndexMap`.** Canonical order by construction, so the
  serialized bytes do not depend on which stream happened to be used first.
  See ADR-0006 for why this matters to `state_hash`.
- **`gen_range_u32` uses rejection sampling.** Compute the rejection threshold
  from the bound and redraw below it. Do not use `% bound`. The loop terminates
  with probability 1 and in practice within one or two draws.
- **`gen_range_i32(lo, hi)`** works over the full `i32` range including
  `lo = i32::MIN, hi = i32::MAX` — compute the span in `u32`/`u64`, never in
  `i32`, so it cannot overflow.
- Serializing mid-stream and deserializing must resume the *identical*
  sequence. This is what makes save/load replay-equivalent.

## Constraints
- No new dependency. Hand-write PCG32 and splitmix64; both are under 20 lines.
  Do **not** add `rand`, `rand_pcg`, `fastrand` or similar — the determinism
  lint bans `rand::` in the consuming crates and a core dependency on it would
  be a standing invitation.
- `std::collections::BTreeMap` only. No `HashMap`/`HashSet`.
- No floats. `gen_bool` is a bit test, not a comparison against 0.5.
- All the multiply/add arithmetic is intentionally wrapping. Use explicit
  `wrapping_mul` / `wrapping_add`, never bare `*`/`+` — the algorithm requires
  wraparound, and under `-C overflow-checks` a bare operator would panic. Put a
  comment on each saying so; this is the one place in the crate where wrapping
  is correct rather than a bug.

## Test
Add `crates/crpg-core/tests/rng.rs`.

1. **Golden vector.** `Pcg32` seeded deterministically produces a recorded
   first 16 `next_u32()` outputs, written literally in the test. This is the
   test that catches a "harmless" refactor silently changing every die roll in
   the project. If it fails, the implementation changed — do not re-bless it
   without understanding why (root AGENTS.md, and workflow plan §11).
2. **Reproducibility.** Same seed, same stream name → identical sequences, over
   a proptest-generated seed and name.
3. **Seed sensitivity.** Different seeds → different sequences (compare the
   first 32 outputs; assert they are not all equal).
4. **Stream independence.** Two different stream names from the same seed
   produce different sequences; and drawing 1,000 values from stream A leaves
   stream B's next 32 outputs unchanged from what a fresh `DeterministicRng`
   with the same seed produces for B. This is the property that lets a new
   system be added without invalidating existing goldens.
5. **Order independence.** Build two `DeterministicRng`s from the same seed,
   touch streams `["a","b","c"]` in one order and `["c","a","b"]` in the other,
   then assert each stream's next outputs match and the two objects serialize
   to identical bytes.
6. **`gen_range_u32` is in bounds and unbiased.** Property: the result is
   always `< bound`, for arbitrary seed and arbitrary non-zero bound. Plus a
   distribution test: for a bound that does not divide 2^32 (use 3, 5 and 7),
   draw 60,000 values and assert every bucket is within 5% of the expected
   count. Assert the same for a power-of-two bound.
7. **`gen_range_i32` boundaries.** In bounds for arbitrary `lo <= hi`; handles
   `(i32::MIN, i32::MAX)`, `(x, x)`, and negative-only ranges without
   overflowing or panicking.
8. **Serde resume.** Draw 100 values, serialize, deserialize, draw 100 more
   from both the original and the clone, assert the two continuations are
   identical. Also round-trip a `DeterministicRng` with three touched streams.

Command that must pass: `cargo test -p crpg-core`

## Out of scope
- `DiceExpr`, dice notation, `2d6+3`. That is `crpg-rules`, T15. Nothing in
  this task should know what a die is.
- Shuffling, weighted selection, `choose`, normal/exponential distributions.
  Add each in the task that first needs it, with its own test.
- A `Rng` trait or any abstraction over `Pcg32`. One concrete type. An
  abstraction here would let a non-deterministic implementation be substituted,
  which is the exact thing this crate exists to prevent.
- Reseeding a live `DeterministicRng`. Build a new one.
- Any other module in `crpg-core`, any other crate.
