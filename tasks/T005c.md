## Task
Add `deny.toml` and a `cargo deny` CI job, and stop CI running twice per push.

## Crate(s)
None. Touches `deny.toml` (new) and `.github/workflows/ci.yml` only.

## Purpose
Two gaps left over from T004. Spec §24 T4 says CI runs "`fmt`, `clippy -D
warnings`, `test`, `cargo deny`" and §15.4 lists `cargo deny check` as step 3
of the integration gate; it was never added, and there is no `deny.toml`.
Separately, `docs/PROJECT_STATE.md` records a known problem: `on: [push,
pull_request]` runs every job twice for any branch with an open PR, which is
the wrong side of the workflow plan §13 "CI wall-clock" metric.

This becomes worth doing now rather than later because T006a adds the first
real dependency (`proptest`, and its ~39 transitive dev-dependencies) —
`cargo deny` with nothing to check is theatre, and `cargo deny` added after a
dependency tree already exists is a licence audit instead of a policy.

## Interface
`cargo deny check` from the repo root, exit 0 on the current tree.

## Behaviour
**`deny.toml`**
- `[licenses]`: allow the permissive set the project already uses —
  `MIT`, `Apache-2.0`, `Apache-2.0 WITH LLVM-exception`, `BSD-2-Clause`,
  `BSD-3-Clause`, `ISC`, `Unicode-3.0`, `Zlib`, `MPL-2.0`. Deny everything
  else, so a copyleft dependency is a CI failure rather than a discovery.
  The workspace is `MIT OR Apache-2.0` and spec §1.5 wants it to stay
  permissive.
- `[bans]`: deny multiple versions of the same crate by default, with an
  explicit `skip` list for the ones the dev tree genuinely duplicates. Keeping
  the skip list explicit is the point — it makes dependency sprawl (workflow
  plan §11) visible in a diff.
- `[advisories]`: deny `vulnerability` and `unmaintained`; `unsound` and
  `notice` warn.
- `[sources]`: allow crates.io only. No git dependencies.

Dev-only dependencies are still checked, but note in a comment that
`proptest`'s tree (authorised by ADR-0006) is dev-only and never linked into a
shipped binary, so a `skip` entry there is not the same concession as one on a
runtime dependency.

**CI**
- Change `on: [push, pull_request]` to run `push` on `master` only, and
  `pull_request` on everything. A branch with an open PR then gets one run,
  not two, and `master` still gets a post-merge run.
- Add a `deny` job. Use `EmbarkStudios/cargo-deny-action` or install the
  binary — either is fine; if the action is used, pin it to a version tag, not
  a moving ref.

## Constraints
- Do not touch any Rust file, any crate `Cargo.toml`, `rust-toolchain.toml`, or
  the lint scripts.
- Do not add a dependency to the workspace. `cargo deny` is a CI tool, not a
  crate dependency.
- Do not relax an existing CI step to make the new one pass.
- If a current dependency fails the licence policy, **stop and report it**
  rather than widening the allow list to make CI green. Widening the policy is
  a decision, not a fix.

## Test
- `cargo deny check` exits 0 locally on the current tree.
- A deliberately broken commit proves the gate: temporarily add a
  GPL-3.0-licensed crate (or set a licence to `deny`) and confirm the job
  fails naming the crate and the licence. Revert it; do not commit it.
- Confirm on the next push that exactly one CI run is triggered for a branch
  with an open PR.

## Definition of done
- [ ] `deny.toml` exists at the repo root and `cargo deny check` is clean
- [ ] The `deny` job is in `ci.yml` and green
- [ ] `on:` narrowed; verified one run per push on a PR branch
- [ ] `docs/PROJECT_STATE.md`'s "Known problems" entry about doubled CI jobs is
      removed in the same commit

## Out of scope
- The self-hosted runner and the slow CI layer (golden replay, perf gate,
  Godot builds). Workflow plan §7 Stage 4 splits those out; they need a runner
  that does not exist yet.
- The merge queue.
- `cargo audit`, `cargo outdated`, dependabot, or any other tool.
- Caching changes, matrix changes, or any other CI restructuring.
- Adding, removing or upgrading any dependency.
