## Task
Run the Lua sandbox spike and record a go/no-go decision.

## Crate(s)
None in this workspace. The work happens in a separate throwaway repo
`C:\CRPG\Dev\spike-lua-sandbox`, which has no dependency on the `crpg`
workspace. This file exists only to make the decision and its rationale
traceable from the main repo, per `docs/HANDOFF.md`'s task-numbering
convention.

## Purpose
Spec `CRPG_ENGINE_SPEC.md` §5.4/§24 (T3) picks Lua 5.4 via `mlua` as the
scripting language for campaign event handlers, and states plainly that
"the sandbox is not optional." Nothing in `crpg-script` should be built on
top of that choice until the sandbox is proven to actually hold: no
filesystem or OS access, bounded execution time and memory, and no source
of nondeterminism that would break replay (§8) or desync a rules-visible
outcome.

## Interface
N/A — not a library API. The spike is a standalone Rust program embedding
`mlua`; no interface is consumed by this workspace.

## Behaviour
In `C:\CRPG\Dev\spike-lua-sandbox` (fresh repo, `cargo add mlua --features lua54,vendored`):

- Build a restricted Lua environment per spec §5.4:
  - Remove `io`, `os` (except a whitelisted `os.time` that returns a
    supplied *sim* tick, not wall clock), `require`, `dofile`, `load`,
    `loadstring`, `debug`, `package`.
  - No raw FFI exposed to scripts.
  - Replace `math.random`/`math.randomseed` with calls into a deterministic
    RNG seeded per invocation from `(tick, entity, call_index)` — a local
    stand-in generator is fine; `crpg-core`'s RNG doesn't exist yet.
  - Replace `pairs` with a deterministic ordered iterator (sort keys, or
    back tables with an insertion-ordered structure) so two runs over the
    same table never diverge in iteration order.
  - Install an instruction-count hook (`mlua`'s `set_hook` /
    `HookTriggers`) that aborts a running script once it exceeds a fixed
    instruction budget.
  - Install a memory ceiling via `Lua::set_memory_limit`.
- Write ten scripted escape attempts, each a `.lua` fixture, covering at
  least: `io.open`, `os.execute`, `require(...)`, `load`/`loadstring` to run
  fresh bytecode, `debug.getupvalue`/`debug.getinfo` tricks, pivoting through
  `getmetatable("")` to reach an unremoved library, walking `_G`/`_ENV` for
  a global that wasn't stripped, a `coroutine` used to try to suspend across
  what would be a tick boundary, and an unbounded table allocation meant to
  blow the memory ceiling.
- Write one infinite-loop fixture to test the instruction budget.
- Write one determinism fixture: a script that iterates a multi-key table
  with `pairs` and calls `math.random` several times, run twice with the
  same seed.

## Test
- All ten escape-attempt fixtures fail closed: each produces a Lua error or
  is refused at load time, never a successful call into the removed
  capability. Assert on the error, not just "didn't crash."
- The infinite-loop fixture aborts within the instruction budget's
  wall-clock equivalent, not by hanging or by the OS killing the process.
- The determinism fixture run twice with the same seed produces
  byte-identical captured output (the `pairs` order and every `math.random`
  draw match).

## Definition of done
- All of the above pass, and are automated (`cargo test` in the spike
  repo), not eyeballed.
- The sandbox setup (global removal, hooks, memory limit, deterministic
  `pairs`/`math.random`) lives in one small module — small enough to be
  copied into `crpg-script` later with minimal changes.
- Written up as `docs/adr/0005-lua-sandbox-spike.md` in this repo: go/no-go,
  the list of escape attempts and their results, the instruction-budget and
  memory-limit values used, and any `mlua` gaps or surprises found (the T2
  precedent — a real upstream defect turned up during that spike — is the
  reason this step isn't skippable).
- `docs/PROJECT_STATE.md` updated with a one-line pointer to the ADR.
