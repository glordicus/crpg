## Task
Add the string `Interner` and the `StatId` / `TagId` handles to `crpg-core`.

## Crate(s)
`crpg-core` (only).

## Purpose
Rulesets declare stats and tags as strings (`"hp"`, `"frightened"`,
`"circumstance"`). The rules kernel compares them millions of times a tick, so
they need to be cheap integer handles at runtime. ADR-0006 Decision 4 fixes the
critical constraint: those handles are **runtime-only** and are never persisted,
because a load-order-dependent integer in a save file silently changes meaning
the moment a ruleset gains a declaration.

## Interface

```rust
// crates/crpg-core/src/intern.rs

/// A handle into an `Interner`. Meaningless without the interner that issued
/// it. Deliberately NOT `Serialize`/`Deserialize` — see ADR-0006 Decision 4.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct StatId(u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct TagId(u32);

impl StatId { pub const fn index(self) -> u32; }
impl TagId  { pub const fn index(self) -> u32; }

/// Interns strings to dense `u32` handles in first-intern order.
#[derive(Debug, Clone, Default, PartialEq, Eq,
         serde::Serialize, serde::Deserialize)]
pub struct Interner { /* private: IndexMap<String, u32> or Vec + IndexMap */ }

impl Interner {
    pub fn new() -> Self;
    pub fn intern(&mut self, s: &str) -> u32;
    pub fn get(&self, s: &str) -> Option<u32>;
    pub fn resolve(&self, id: u32) -> Option<&str>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    pub fn iter(&self) -> impl Iterator<Item = (u32, &str)>;   // ascending id
}

/// Two separate namespaces, so a `StatId` can never be used as a `TagId`.
#[derive(Debug, Clone, Default, PartialEq, Eq,
         serde::Serialize, serde::Deserialize)]
pub struct Interners { /* private: stats: Interner, tags: Interner */ }

impl Interners {
    pub fn new() -> Self;
    pub fn intern_stat(&mut self, s: &str) -> StatId;
    pub fn intern_tag(&mut self, s: &str) -> TagId;
    pub fn stat(&self, s: &str) -> Option<StatId>;
    pub fn tag(&self, s: &str) -> Option<TagId>;
    pub fn resolve_stat(&self, id: StatId) -> Option<&str>;
    pub fn resolve_tag(&self, id: TagId) -> Option<&str>;
    pub fn stats(&self) -> &Interner;
    pub fn tags(&self) -> &Interner;
}
```

## Behaviour
- `intern` is idempotent: interning the same string twice returns the same
  handle and does not grow the table.
- Handles are dense and assigned in first-intern order, starting at 0.
- `iter` yields ascending id order, which is also first-intern order.
- `StatId` and `TagId` are distinct types with no conversion between them and
  no public constructor from a raw `u32`. Crossing the namespaces must be a
  compile error, not a convention.
- **`StatId` and `TagId` must not implement `Serialize` or `Deserialize`, and
  must not implement `Display`.** Both are ways the handle escapes into
  persisted data. This is the whole point of the task; if a later task needs
  the string, it asks the interner for it. Put this in a `//!` module doc with
  the ADR reference so the next agent does not "helpfully" add the derive.
- `Interner` itself *is* serializable, as an ordered list of its strings, for
  diagnostics and tooling. That is not a back door: deserializing an
  `Interner` gives you the same strings in the same order, but the handles that
  were valid against some *other* interner are still meaningless.
- Interning is not fallible. There is no ruleset large enough to exhaust `u32`.

## Constraints
- Dependencies: `indexmap` (already a workspace dependency) and `serde`. No new
  dependency.
- No `HashMap`/`HashSet`. `IndexMap` or `BTreeMap`.
- No floats, no clock, no threads.
- No global or thread-local interner, and no `lazy_static`/`OnceLock`
  singleton. An ambient interner is how a "harmless" `Serialize` impl becomes
  possible, and it is a hidden input to a supposedly pure simulation. The
  interner is owned by whatever loads the ruleset and passed explicitly.

## Test
Add `crates/crpg-core/tests/intern.rs`.

1. **Idempotence.** Property test: interning a `Vec<String>` in any order, then
   re-interning every string, returns the same handles and leaves `len()`
   equal to the number of distinct strings.
2. **Round-trip.** `resolve(intern(s)) == Some(s)` for arbitrary strings,
   including empty, non-ASCII, and strings differing only in case.
3. **Density and order.** After interning n distinct strings, the handles are
   exactly `0..n`, and `iter()` yields them ascending.
4. **`get` vs `intern`.** `get` on an un-interned string is `None` and does not
   mutate; `resolve` on an out-of-range id is `None`.
5. **Namespace separation.** Interning `"hp"` as a stat and `"hp"` as a tag
   yields handles that are independent — a compile-time property, so assert it
   by checking that the two namespaces' `len()` counts move independently.
6. **`Interner` serde round-trip** preserves order and handle assignment.
7. **The serde ban is documented, not tested.** A negative trait-bound test
   needs `trybuild`, and a dependency for one compile-fail case is not worth
   it at this stage. Instead: a `//!` module doc on `intern.rs` stating the
   ban and citing ADR-0006 Decision 4, and the `AGENTS.md` known-trap entry in
   the checklist below. The real guard is that adding the derive requires
   editing a file whose first paragraph says not to.

Command that must pass: `cargo test -p crpg-core`

## Out of scope
- `StatBlock`, `StatValue`, `TagSet`, modifiers, anything that *uses* a
  `StatId`. All of that is `crpg-rules`, T14. This task builds the handle and
  the table, nothing that consumes them.
- `Serialize`/`Deserialize`/`Display` on `StatId` or `TagId`, under any
  justification. If a task appears to need one, that task is wrong — it needs
  the string.
- A frozen/sealed interner phase, id reassignment, or canonical sorted ids.
  Considered and rejected in ADR-0006; the explicit-string approach makes it
  unnecessary.
- `AbilityId`, `EffectId`, `ModTypeId` or any further namespace. Add each in
  the task that first needs it, following this pattern.
- Any other module in `crpg-core`, any other crate.
